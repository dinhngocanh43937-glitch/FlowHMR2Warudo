# 参数与运行

参数由GUI保存到本机 `state/parameters.json`，不会提交Git；停止输入后修改并应用，下次启动输入生效。

| 参数 | 范围 | 影响 |
|---|---|---|
| 目标帧率 | 20/25/30 | 目标采样/输出节奏，不代表同等频率的新推理结果；降低可能减负 |
| SAM间隔 | 1–6 | 越大识别越稀疏、负担更低，可能损失快速动作细节 |
| 身体层数 | 1–6 | 更多计算可能改善姿态，不保证单调提升 |
| Flow步数 | 1–16 | 更多求解计算，通常增加耗时 |
| 检测尺寸 | 416/640 | 640对小人物可能有利，但代价更高 |
| 手部 | off/fast/full | off减负，开启后增加手部计算；需画面和模型支持 |
| 手部层数 | 1–6 | 仅开启手部时有意义，增加计算不保证更准 |
| 延迟预算 | 200/300/400/500/600/700/800/1000ms | 调低减少缓冲余量，可能加剧欠载，不是计算加速开关 |
| SAM批次 | 1/2 | 1可能降低批处理等待，2可能提高吞吐；实际需测量 |

建议先800ms/批次2，固定其他参数后逐项测试。已验证硬件上的短测不代表所有设备。
「8GB低负载」填入SAM间隔6、身体1层、Flow1步、检测416、手部off、手部1层，不修改FPS/延迟/批次；仍需应用。

首次模型加载或编译预热较长。监控以欠载的增量而非累计值判断本轮稳定性，实测引擎延迟不包含所有渲染/显示延迟。预览固定首帧，监控每5秒刷新；有意避免网页/视频预览和绘图负担。

若出现明显卡顿，先减少Warudo窗口渲染负担与其他GPU程序，再调低计算参数；低预算可能适得其反。
